1 手册概述

1.1 适用范围与读者

本手册面向现场部署与日常操作人员，覆盖从硬件接线、软件环境安装、配置文件设置、程序启动到界面操作与故障排查的完整流程。读者无需了解软件内部实现；涉及设计原理的内容请查阅配套的《设计报告》。

1.2 阅读前提

（1）已备齐两台 EWD611-868NW33（485 版）数传图传模块、一台网络摄像头、一根 485 转 USB 转换器与相应线缆；（2）操作笔记本为 Windows 10/11，已安装 Anaconda 或 Miniconda；（3）已获取本项目目录（含 run.py、src、config 等）。

1.3 术语约定

术语含义
远端节点部署在被控现场的 EWD611 模块，接摄像头与 485 待控制设备
本地节点连接操作笔记本的 EWD611 模块（网口 + 485 转 USB）
AT 指令配置图传模块参数使用的文本指令，形如 AT+TXPOWER=15
透传与待控制设备之间的 485 原始数据双向转发（Hex 或 ASCII）
RSSI / EVM无线信号强度（dBm）/ 误差矢量幅度（dB），链路质量核心指标
AP / STA模块组网角色：热点端 / 接入端。本部署默认本地为 AP、远端为 STA

2 硬件安装与接线

2.1 装箱核对

两台 EWD611-868NW33（485）模块（天线 2 根、电源 2 个）、网络摄像头（电源、网线）、485 转 USB 转换器、USB-A 线。模块说明书位于项目目录：EWD611-868&915NW33(485)_UserManual_CN_V1.1.pdf 与 网络摄像头_UserManual_CN_V1.0.pdf。

2.2 接线总览

2.3 远端节点

（1）摄像头网线插入远端 EWD611 的网口（摄像头供电用原装电源）；（2）待控制设备的 485 总线 A/B 两线接入远端模块 485 端子；（3）安装天线后接通模块电源。摄像头出厂 IP 若与模块网段不一致，先用摄像头说明书的方式把摄像头 IP 设置到与远端模块同一网段。

2.4 本地节点

（1）本地模块网口用网线直连笔记本网口（或经同一交换机）；（2）模块 485 端子 A/B 接 485 转 USB 转换器，转换器插笔记本 USB；（3）安装天线后通电。Windows 设备管理器出现新 COM 口即正常（常见芯片为 CH340/CP210x，缺驱动时装厂商驱动）。

2.5 上电自检

两端模块上电约 30 秒后链路指示灯进入常亮/规律闪烁的组网状态；随后在笔记本上按第 3、5 章安装并运行 python run.py selfcheck，无硬件也应全部通过，再按第 4 章填实际参数。

4.1 生成配置

conda run -n ewd611-hmi python run.py config --init

4.2 配置总览

4.3 串口（serial 段）

关键字段：port（留空启用 auto_detect: true 按 VID 猜测，常见芯片 VID：1A86、10C4、2341）、baudrate: 115200（模块 RS485 固定，勿改）、rx_idle_gap_ms: 30（分帧空闲间隔）。探测命令：

python run.py ports --probe    # 列串口并给出最像 485 转 USB 的口

4.4 视频（video 段）

默认经 url_template 由 IP/端口/账号拼 RTSP 地址，channel: 1、stream_index: 1（子码流 704×576，低带宽优先）。若摄像头 URL 格式不同，直接写死 url: 字段即可覆盖模板。transport 选取流协议（tcp/udp，代码默认 tcp）：TCP 稳定不花屏但重传缓冲抬高端到端延迟，UDP 延迟低但丢包可能花屏；也可以不动文件，直接在视频页工具条"传输"下拉里切换——即选即效并自动写回本文件，出现花屏切回 tcp 即可。延迟调优三键：buffer_ms（收流窗口，代码默认 300 ms，现场建议 100 ms 起步）、pacing_frames（放帧队列容量，默认 5，现场 3）、max_dwell_ms（放帧停留时间预算，默认 120 ms，超预算即丢弃积压只放最新帧）；render_fps_limit: 25 限渲染帧率。画面右下角 OSD 显示"显示N帧 · 停留Xms [跳帧M]"：若停留持续贴住预算且跳帧猛涨，说明解码跟不上流速率，先调小 buffer_ms 或切 udp 试验。

4.5 AT 与 UDP 通道（at / udp_at 段）

默认 channel: serial 走 485 转 USB。timeout_ms: 1500、retries: 2；wake_gap_ms: 300 用于总线静默唤醒；pause_passthrough: true 使 AT 事务期间暂停透传避免串帧。local_role: ap、remote_role: sta 与本部署组网角色一致。若 485 口被占用或想走网口，改 at.channel: udp 并填 udp_at.target_ip 为本地模块网口 IP（端口 0 表示按候选端口自动探测：5000/5001/8000/8080/4000/4001/10000/20000/554）。

4.6 链路与告警阈值（link 段）

auto_poll: true 启动即周期轮询（3 秒/轮，读取顺序见 read_order 12 项 + AP 端附加 WNBCFG/STA_INFO）。告警阈值：rssi_warn: -85、rssi_crit: -92、evm_warn: -20、loss_warn_percent: 5；快照超 stale_after_s: 12 判过期。

4.7 指令模板（config/templates.yaml）

透传指令模板库，自带 3 条示例：Modbus 读保持寄存器（crc16_append: true 自动补 CRC）、带占位符的通道开关（下发前填 {ch}/{reg}）、ASCII 查询（mode: ascii，支持 \r\n 转义）。校验命令：

python run.py templates            # 列出并校验
python run.py templates --value ch=1 reg=0010   # 带占位符试算

4.8 机器人遥测（telemetry 段）

本段控制视频页底部遥测状态栏的数据来源与行为，默认全部开启：

键默认说明
enabledtrue遥测解析总开关，关闭后状态栏保持 --
log_csvtrue每秒把样本批量冲刷到 data/telemetry_日期.csv
stale_after_s3.0超过该秒数无有效帧判"遥测中断"，状态栏置灰并告警一次
display_throttle_hz2.0界面刷新节流（限 0.5~20），只影响显示，不影响留痕
frame.protocolwheeltec解析器三选一：wheeltec（官方底盘 24 字节反馈帧，0x7B 头 0x7D 尾，实机默认）、binary（AA 55 头 20 字节定长占位帧）与 ascii（TLM,... 校验行占位）保留作备选
frame.header_hex"AA 55"二进制帧头，仅 frame.protocol=binary 时生效；用 wheeltec 无需调整
status_map0 待机 / 1 自动驾驶 / 2 遥控 / 3 急停状态码到中文的映射，可增改
battery.low_voltage_v22.0电池电压低于该值红字告警（跳变只发一次）
curve.window_s / series60 / [voltage, speed]迷你曲线窗口秒数与序列（可选 voltage/current/soc/speed）
mock.enabled"auto"auto 跟随 app.mock；也可强制 "true"/"false"

联调确认机器人侧实际使用 Wheeltec 底盘协议，已实现为默认解析器；如需换协议仅需改 frame 两键，界面与服务无需改动。查看生效值：

python run.py config | findstr telemetry   # 打印生效配置并过滤遥测段

4.9 机器人运动控制（motion 段）

本段控制视频页方向盘与键盘四向运动的速度上限、加减速过程与帧格式，默认全部开启。按住方向键时速度按"加速斜率"爬升到限速满值，松开后按"减速斜率"滑到 0 并自动补发一次停止帧：

键默认说明
enabledtrue运动控制总开关，关闭后方向盘停用并标注"运动控制已禁用"
max_linear_speed1.0线速度上限 m/s（上/下键的目标值，机器人限速务必按实际改）
max_angular_speed0.5角速度上限 rad/s（左/右键，左转为正）
linear_accel / linear_decel0.5 / 0.8线速度加速/减速斜率（m/s²）：按住约 2 秒到满速，松开约 1.25 秒滑停
angular_accel / angular_decel0.3 / 0.5角速度加速/减速斜率（rad/s²）
send_period_ms100按住期间运动帧周期重发间隔 ms，抗丢包；空闲不重发
stop_on_focus_losstrue窗口失焦或切离视频页立即速度清零并补发停止帧
frame_protocolwheeltec下行组帧方式：wheeltec 按官方底盘协议组 11 字节速度帧（0x7B 头 0x7D 尾，前向/横向速度 mm/s、角速度 mrad/s 各填 16 位大端，BCC 校验）；template 改用 frame_hex 模板组帧
frame_hex"AA 01 {vx} {vr}"仅 frame_protocol=template 时生效；{vx}/{vr} 填速度×100 的有符号 16 位 hex（0.5→0032、-0.5→FFCE），机器人协议不同只需改这一行
invert_angularfalse角速度符号翻转开关：Wheeltec 协议逆时针（左转）为正；底盘反装导致转向相反时置 true

查看生效值：python run.py config | findstr motion。临时试跑：python run.py gui --set motion.max_linear_speed=0.5。

6.1 主窗口与导航

6.2 视频页

配置正确时自动连接并显示子码流画面；顶部按钮：连接/断开、开始/停止录制、抓图，另有"传输"下拉可在 tcp/udp 间即时切换取流协议——即选即效并自动写回配置文件，出现花屏切回 tcp 即可。状态条显示分辨率与实测帧率；画面右下角 OSD 叠加"显示N帧 · 停留Xms [跳帧M]"：停留持续贴住时间预算（默认 120 ms）且跳帧猛涨，说明解码跟不上流速率，调优方法见 4.4。无摄像头时页面上报连接失败原因，其余功能不受影响。

页面最下端为遥测状态栏，实时显示机器人侧经 485 送来的关键信号：运行状态（待机/自动驾驶/遥控/急停）、电池电压、电流、剩余电量、速度、经纬度与定位状态（含最后更新时刻）。当前 Wheeltec 反馈帧不含电流、剩余电量与 GPS，这几格按缺数据规则显示 --；电压、速度与状态为帧内实数。配色规则：缺数据一律显示 --；遥测中断（超过 3 秒无有效帧）整条置灰并在恢复后自动转回正常；电池电压低于阈值（默认 22.0V）或状态为急停时对应格红色加粗，鼠标悬停可见原因。数字下方是近 60 秒双序列迷你曲线（电压与速度各自归一化，看趋势用）。速度格鼠标悬停可见累计里程（按速度积分估算，断档不补，只在表格与 CSV 里给出）；右侧 导出 CSV 把当前场次遥测样本表另存为文件（可 Excel 打开）。仿真演示模式下状态栏数字与曲线持续滚动，行为与真实链路完全一致；数据来源与配置见 4.8 节。

状态栏上方右侧为运动方向盘：十字排布"前进/后退/左转/右转"四个按钮，中心行显示"行/停"，下方读数实时显示目标速度与实际速度回显（如 vx +0.20 vr +0.00）。按住即按加减速斜坡趋近限速满值，松开即滑停到 0 并补发停止帧；键盘 ↑ ↓ ← → 与按钮完全同义（页面焦点在视频页即可，无需点击按钮）。左上/右上等斜向可两键组合。安全行为：窗口失焦或切到别的页面会自动急停；未装配或 motion.enabled=false 时方向盘整块置灰并写明原因。指令帧经 485 透传发给机器人，限速与斜坡参数见 4.9 节。

6.3 透传控制台页

（1）输入区选 Hex 或 ASCII 模式；（2）直接输入 01 03 00 00 00 02（空格可省）点"发送"，或从模板下拉选择后填占位符下发；（3）勾选 CRC16 时自动追加校验字节；（4）下方列表显示收发双向报文与时间戳。回复超时给出提示但不阻断。

6.4 数据页

以九列表格（时间/方向/种类/端点/通道/Hex/ASCII/字节/备注）展示对端经 485 送来的原始数据流与本机发出报文、最近参数视图快照与计数；列宽可自由拖动，备注列随窗口伸缩。备注列对机器人帧自动给出语义解读——下行显示"速度指令：前向速度 0.055 m/s，角速度 0.000 rad/s"（横向速度非零时补一段），上行显示"底盘反馈：使能，前向速度 …，角速度 …，电压 …V"；帧头帧尾或校验不过的字节宁可不解释，其余数据留空按原始流查看。支持暂停滚动与清空，便于比对报文。

6.5 电台配置页

表单按参数注册表自动生成，分普通参数、"信道遥测（只读）"、"动作指令（只写）"三组。操作：①"读取全部"刷新各字段实际值；②修改可写字段（下拉选项/数值范围由程序校验）；③"预览"查看将要下发的 AT 行而不发送；④"下发"逐条执行并在日志页留痕，失败字段标红并给出模块应答。频点类字段界面按 MHz 显示，程序内部自动换算。"读取全部"在后台线程执行：期间按钮变"读取中…"并置灰（避免叠加请求），界面不会因某个参数不应答而冻结；成功的参数回填"当前值"列，整体结果（如"成功 12/18"）与失败原因写在主窗口底部状态栏。若某条读取因通道根本没打开而失败，其余参数直接标记跳过，不会刷出二十多条重复失败。

6.6 信道监控页

上半部为 RSSI（绿）/EVM（蓝）双轴历史曲线，虚线为 -85 橙 / -92 红告警阈值；"跟随刷新"勾选时新快照自动入曲线（按时间戳去重）。中部链路指标卡：连接状态、频点、带宽、MCS、功率、STA 数；退化（degraded）与错误以醒目色提示。下半部 STA 列表九列（MAC、RSSI、EVM、收发 MCS、收发/丢包计数）。按钮：读取一次、开始/停止轮询、清空曲线。进页自动回填最近 30 分钟历史。

6.7 日志页

三源合屏：AT 流水（方向符号 ▶/?/✎/⚡/⇓、RTT、应答摘要、失败标红）、告警（⚠ 级别色）、运行日志。工具条：来源复选框 ×3、级别下拉（全部/警告及以上/仅错误）、清空视图、录制文件路径、自动滚动。过滤只影响显示，计数栏始终显示收到的条数；缓冲区上限 4000 行自动截旧。

7 常见问题排查

7.1 串口与 AT

现象可能原因处理
界面提示"未检测到串口"转换器未插/缺驱动/被占用重装 CH340/CP210x 驱动；关闭占用程序；run.py ports --probe 后把端口写入 serial.port
AT 全部超时485 极性接反/波特率不符/模块未上电核对 A/B 极性；模块固定 115200 8N1；确认模块指示灯
偶发应答错位总线空闲间隔不适配调大 at.wake_gap_ms 或 serial.rx_idle_gap_ms
想不占 USB 口配参数—at.channel: udp + 填 udp_at.target_ip，与透传并行
点"读取全部"没反应，日志页也查不到下发记录AT 通道压根没打开（COM 口未识别 / 配置与实际不符）按下面"读取没反应"一条按序自救；改完配置必须重启程序

点"读取全部"没反应、AT 日志页一条记录也没有

先分清两种现象：①按钮变"读取中…"后状态栏给出失败原因、日志页有红色失败行——指令已经上线，问题在模块侧（极性、波特率、供电、AT 使能），按上表继续排查；②状态栏提示"AT 通道未打开"、日志页一片空白——指令根本没上线。当前版本已把"通道未绑定传输层""通道未打开""发送失败"三条原本静默的路径全部补上日志留痕，所以日志页空白只可能是"没点"，不再是"点了没留痕"。

通道没打开时按序自救：①看主窗口底部状态栏的"启动提示"——程序启动时会自动打开 AT 通道，失败不弹窗，原因（端口不存在 / 被占用 / 权限不足）只写在这里；②命令行执行 python run.py ports --probe，确认 485 转 USB 是否已被系统识别出 COM 口，认不出就先装 CH340/CP210x 驱动或换个 USB 口；③把识别到的端口写进 config/app.yaml 的 serial.port（留空且 serial.auto_detect 为 true 时，按 serial.preferred_vids 里的厂商 ID 自动挑一个空闲口），并核对 serial.baudrate（模块固定 115200 8N1）；④改完配置必须重启程序：界面内没有手动重开串口的入口，通道只在启动时打开一次。

想排除界面因素，可在带硬件的情况下跑一次 python run.py selfcheck --real：它的 AT 检查段会逐条读参数并打印结果，与图形界面走的是同一套协议栈。若自检能读通、界面读不通，问题在配置装配（python run.py config 查看生效值）；若自检同样报"通道未打开"，回到上面 ①—④。

7.3 链路与告警

现象可能原因处理
RSSI 持续低于 -92（红）距离过远/遮挡/天线未装检查天线与视距；抬高安装位置；缩短距离
mock 模式反复告警仿真随机游走特性属预期演示效果，实机不会出现
快照"过期"提示轮询中断超 12 秒查 AT 通道状态；必要时点"读取一次"验证
参数读取部分失败（退化）某条 AT 不支持当前角色核对 local_role/remote_role 与模块实际组网角色

遥测状态栏一直显示 -- 或置灰

按序检查：① telemetry.enabled 是否为 true；② 对端是否确实在发送遥测帧且走 485 透传通道（数据页应能看到对应接收字节流——状态栏只是旁路解析，数据页没有数据说明链路本身未收）；③ telemetry.frame.protocol 与对端帧格式是否一致（wheeltec/binary/ascii 三选一，默认 wheeltec 即 0x7B 头 0x7D 尾的 24 字节底盘反馈帧；binary 占位帧头 AA 55 可改）；④ 置灰只在"超过 stale_after_s 无新有效帧"时出现，恢复即自动转正常。演示时可直接 python run.py gui --set app.mock=true --set telemetry.mock.enabled=true 看动效。

状态栏数字刷新很慢

属正常：界面按 display_throttle_hz（默认 2 次/秒）节流刷新，只影响显示频率；数据留痕与 CSV 落盘始终是全量的，导出文件行数明显多于状态栏刷新次数是预期行为。

方向盘置灰或按键无动作

方向盘整块置灰并带原因文字时按原因处理："运动控制已禁用"改 motion.enabled: true；"未装配运动服务"说明启动时被装配开关旁路，正常安装不会出现。按钮可点但机器人不动：① 确认 485 通道已启动（控制台页能正常收发即通道可用，通道未开时运动帧会被拒发）；② 核对 motion.frame_protocol（默认 wheeltec 即官方 11 字节速度帧；非 Wheeltec 协议时切 template 并改 frame_hex）与机器人实际指令格式（可在数据页查看 kind=motion 的发出字节与备注）；前进/后退正确但转向相反时置 motion.invert_angular: true；③ 速度读数一直为 0 属预期——松开后滑停归零，按住期间才会爬升。

切走页面或点了别的窗口，机器人为何停了

这是安全设计：默认 stop_on_focus_loss: true 下，视频页失焦即急停补发停止帧，防止焦点被抢后"按键悬空持续运动"。确有需要保留运动状态时把该键改为 false（不建议）。

一直按住方向键，速度却"递增一下又回零"

早期版本对键盘长按的"自动重复"处理不对称：重复的"按下"被正确吞掉，但操作系统在长按时会夹带重复的"释放"事件被当成了松手，于是目标速度被清零、速度爬到一半就回落，而随后的重复"按下"又已被过滤，导致按住不动却回不来。现已让"释放"与"按下"对称——只有真正松手那一次（isAutoRepeat=false）才释放方向。若仍遇到按住不回，请确认窗口焦点始终在视频页（失焦急停是另一条独立的安全路径，见上一条）。用方向盘按钮鼠标按住则不受键盘自动重复影响。
